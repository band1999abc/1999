【② 「ひび割れ」のクジラ位置】
━━━━━━━━━━━━━━━━━━

Android実機で以下の挙動を確認しました。

1. 「ひび割れ」歌詞ページを開く
2. クジラが上部に寄った不自然な位置にいる
3. そのままページを下方向へスクロールする
4. クジラは上部に残ったままで、正しい位置に移動しない
5. 一度ページ最上部まで戻る
6. その後もう一度スクロールすると、クジラが正しい位置に戻る

つまり、
「ページを開いた直後の初期位置」と
「最上部へ戻った後の位置」で挙動が違います。

これは単純なtopの値の問題ではなく、
クジラの位置計算・初期化・スクロール・viewport変更時の再計算タイミングに問題がある可能性があります。

【調査してください】

whale.js と関連CSSを中心に、

- 初期位置の計算タイミング
- DOMContentLoaded
- load
- requestAnimationFrame
- resize
- orientationchange
- visualViewport.resize
- ResizeObserver
- scroll
- ページスクロール位置
- window.innerHeight
- visualViewport.height
- document.documentElement.clientHeight
- position: fixed / absolute / sticky
- transform
- top
- cardの高さ
- 歌詞コンテンツの高さ

など、現在どの値を基準にクジラの位置を決めているのか確認してください。

特に、
「ページを一度最上部まで戻した後だけ正しくなる」
という症状から、スクロールイベントを契機に再計算されている可能性も確認してください。

【重要】

単純に
top: XXpx
のXXを変更するだけの修正は禁止です。

また、クジラの
- サイズ
- 画像
- 透明度
- 色
- filter
- アニメーション
- アニメーション速度
- デザイン

は変更しないでください。

他のページのクジラにも影響を与えないでください。

「ひび割れ」だけの位置調整が必要なら、ひび割れ固有の処理として実装してください。

最終的には、
ページを開いた直後から、スクロール開始時、スクロール中、最上部へ戻った後まで、
一貫して正しい位置になることを目標にしてください。

【⑥ 不要なスクロール】
━━━━━━━━━━━━━━━━━━

こちらも実機でまだ問題があります。

「コンテンツが画面内に収まっているのに、必要のない縦スクロールが発生するページ」があります。

ただし、今回の要件は
「スクロールをなくす」
ではありません。

以下のようにしてください。

- コンテンツが表示領域内に収まる
  → 不要なスクロールなし
- コンテンツが表示領域を超える
  → 自然にスクロール可能
- 将来コンテンツが増える
  → 自動的にスクロール可能
- iPhone / iPad / Android / PCで表示領域が違う
  → 端末ごとに必要ならスクロール可能
- Safari / ChromeのブラウザUIによるviewport変化にも対応

【調査を優先】

現在のCSS/JSから、

- html
- body
- main
- page container
- card
- 100vh
- 100dvh
- min-height
- height
- padding
- margin
- gap
- position
- transform
- overflow
- whale関連の高さ
- Footer
- ナビゲーション
- 各ページ固有のwrapper

を調査してください。

特に「ページ全体の高さがviewportより数px〜数十px大きくなっている原因」を特定してください。

全体に
overflow:hidden
を追加して隠すだけの修正は禁止です。

コンテンツが増えたときにスクロールできなくなる実装も禁止です。

【重要】

実際に不要なスクロールが発生するページを特定し、
「なぜそのページだけスクロールが発生するのか」を確認してください。

- Live
- After Hours

長いDiary / Musicなどのスクロールは正常なものなので、
それを消す方向には変更しないでください。
